# Bounded old-Oz FAS load-condition diagnostic

This separate diagnostic preserves the failed guarded table (35/36), including the failed old-Oz FAS cold startup and its subsequent cache-qualified reload. It does not retry that matrix into success or provide a replacement performance table. It admits the original old-Oz producer and matching FAS before creating a declared diagnostic copy. Original package/runtime asset bytes and session wrapper remain exact. The child wrapper and one root-load startup command are explicitly derived; their original and derived hashes are retained.

The plan contains at most twelve fresh browser/page/CAS-worker cold starts, all old-Oz with its own FAS. Each case has the original 300-second outer watchdog and 240-second initialization timeout. The driver stops on the first captured condition or other core failure, including setup or cleanup failures, records that failure without retry, and marks the remaining planned cases as unattempted. Whole diagnostic success requires all twelve cases and every guard to pass. `diagnosticOnly: true`, `acceptance: false`, and `fullComparisonComplete: false` remain explicit even on success.

Pinned Maxima source explains why the retained generic message lacks a cause. `$load` calls `load-and-tell` and `loadfile`; the latter wraps `cl:load` in Maxima's `errset` macro. Its error handler returns NIL when the dynamically special `MAXIMA::ERRSET` is NIL, discarding the condition, after which `loadfile` emits `loadfile: failed to load ...`. An ordinary NIL return from `cl:load` becomes a nonempty values list and does not take this failure path. `draw.lisp` loads `defsystem.lisp` and `draw.system`, then invokes `mk:oos` with `:compile`. The generic failure does not distinguish those nested steps. Maxima debug mode cannot reconstruct a condition already swallowed by `errset`.

The exact original root-load command is replaced by one physical `:lisp` form. It loads the trusted helper from a separately mounted MEMFS path, then calls the helper through `find-symbol` after its package exists. The helper verifies the root path, dynamically binds `MAXIMA::ERRSET` to T only around the original `$load`, and installs a standard `handler-bind` observer for ERROR conditions. That observer prints at most one condition type and report, then returns and declines the condition. Original propagation continues. There is no `CL:LOAD` or function-cell interposition, debugger loop, TRACE, CPU sampler, filesystem profiler, collector probe, or rebuild of admitted artifacts. Ordinary startup-requested Lisp compilation remains possible.

Changing ERRSET changes error propagation and may expose otherwise handled or benign conditions. A pass or a different condition under this diagnostic does not identify the original cause. Even a relevant condition requires comparison with the original failure and separate interpretation. The helper's output is bounded (type128/report2048 characters), but rendering a condition into a string is not an allocation bound. Logger failure attempts a bounded fallback marker inside its own error handler; failure of that fallback is also declined so it cannot replace the original condition. A malformed/missing/overflowed diagnostic never counts as absence of a condition. Live Lisp behavior remains a CI diagnostic boundary; local tests do not evaluate Lisp.

The shared reviewed stdout guard is unchanged: anchored fatal diagnostics remain sticky, marker order remains mandatory, and later READY cannot rescue a failed startup. A small additional declared child bridge sends the first bounded condition line immediately through the existing diagnostic/onEvent channel. The parent persists partial progress while initialization is still pending, preserving an observed condition even if later propagation hangs before READY or a fatal guard receipt. The guard receipt also retains the bounded capture independently of its rotating stdout tail. Final success requires consistent immediate and receipt capture, one armed marker, no condition, no logger failure, and no overflow. The guard proves the observed ordered markers and absence of recognized fatal diagnostics; it does not prove every possible startup error or a same-evaluation root-return sentinel.

Successful initialization still requires one matching FAS read and zero source fallback, fresh worker/buffers, first logical check before grades or warmups, all ten typed controls, positive and negative grades, policy checks, three admitted native programs, 100 explicit GC/live-object checks, caught-error recovery, and four plotting-policy checks. Failed sessions are terminated and poisoned; stop acknowledgments must establish rejection of subsequent calls. Each saved sample and compact report share an immutable snapshot. Later console/page failures are retained separately and fail the diagnostic. Progress lines and hardware metadata are outside timed blocks; raw elapsed observations are retained for context without diagnostic performance medians.

Local validation uses the trusted derivation and synthetic JavaScript sessions/transports, original manifests and failed stdout as data, and lexical Lisp balance checks. It does not run a browser, CAS, Lisp, Wasm, or artifact program. All original frozen sources and failed evidence remain untouched.
