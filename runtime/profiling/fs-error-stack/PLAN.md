This isolated experiment reuses accepted ECL-Oz/Maxima-O2 runtime and its own matching STACK FAS from full run 40108653819, attempt 1. It does not rebuild ECL, Maxima, Wasm modules or FAS, and does not change production or the separate six-cell comparison. Admission verifies completed successful producer metadata, both expected jobs, exact artifact metadata and ZIP digest, all 3,404 ZIP file records, complete 223-row package inventory plus itself, the original source overlay/compiler evidence, 71 exact committed recipe files and all 79 runtime assets. The original three site manifests, 77 embedded STACK files, matching FAS descriptor/content and accepted browser capture are checked before derivation. Each staged arm has 87 files. The old archive omits runtime-preload.json: its exact 3,470,156 bytes and archived manifest SHA are reconstructed from the admitted runtime assets using the pinned serialization. This reconstruction is explicitly recorded. It is not compilation or an archived member.

The control retains all original runtime assets. The experimental arm changes only the exact pinned `ErrnoError` class body inside maxima.js; three site manifests change only its bytes/hash and the explicit derived runtime identity. The original JavaScript is 1,239,434 bytes, SHA256 `385763ca1038fac02e8f7d247a8d808997238b03ba1919ce2f4dcec482fdb101`. A unique constructor anchor, complete constructor hash and complete original file hash must agree. No generated artifact JavaScript is evaluated by admission. Original and derived JavaScript plus the raw derivation JSON are retained.

For numeric errno 44/54 only, the intervention computes the original message before changing the stack limit, requires an own writable finite numeric Error.stackTraceLimit data descriptor, temporarily sets its value to zero solely around `super(message)`, and restores the exact descriptor in `finally`. Missing, accessor, inherited, read-only, nonnumeric and nonfinite cases retain normal construction. The original class, prototype, constructor identity, fresh object, errno and code loop remain. Non-44/54 errors retain normal stack capture. Expected-error call frames are intentionally lost; unexpected errors carrying these same errnos also lose frames but remain errors. This is a diagnostic tradeoff, not a general exception-suppression or production change.

One actual-child capability receipt is emitted after descriptor restoration and errno/code assignment on the first eligible construction. A collision-safe Module key prevents repeat/reentrant observations, and observer exceptions cannot change filesystem error behavior. The receipt includes descriptor support/restoration, the original stack limit, whether suppression was applied and first-only native stack frame evidence. Attribution requires a positive original limit and zero captured native frames after suppression. Missing, malformed, unsupported, unobserved or ineffective treatment cannot count as a valid causal comparison. The control must emit no treatment receipt. Receipt overhead belongs to the intervention and is not subtracted.

Both arms additionally use the same separately declared derived child stdout observer. It scans completed startup lines for anchored fatal diagnostics and ordered existing LOAD-BEGIN/LOAD-END/READY markers, retains a bounded tail, and emits a bounded receipt. The original child hides these lines from the external harness. This shared observer is required for honest startup-error admission; neither whole site is described as an unchanged accepted site. Its original/derived bytes and raw proof are separately bound. Original startup commands, Maxima session wrapper and runtime assets are unaffected by this observer. The existing markers do not prove a same-evaluation root-load return, and the observer does not claim that stronger contract. Console errors remain separately checked.

The clean runner uses original versus experimental arms, each source versus its own FAS, at least three repetitions, cold plus same-browser-profile reload: 24 measurements. It alternates arm and source/FAS ordering and uses fresh worker/session state with confirmed termination before reload. No TRACE, CDP, CPU quota, filesystem hook or extra CAS warmup precedes the first logical-validation call. It retains all ten typed checks, exact three native-rational programs, 100 full-GC acknowledgments with retained object, error/recovery and four no-plot controls, with the existing 300-second watchdog. Readiness, STACK duration, first logical/positive/negative grade, warm grade/arithmetic and the explicit readiness-plus-first-work sum are reported separately. Original runtime flags are fixed at ECL-Oz/Maxima-O2 in both arms.

The n=1 TRACE pilot showed substantial sampled ErrnoError intervals, split between open and readlink paths, but samples are not exact CPU durations or promised recoverable work. FS.readlink may throw errno 28 as well as 44, and the raw CPU profile does not record errno arguments. This experiment remains narrowly 44/54; its coverage and possible gain are unknown before measurement. Matched n=3 results are descriptive and retain order/cache/runner variation; no speedup or default-promotion claim is preauthorized.
