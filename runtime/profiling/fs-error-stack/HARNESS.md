# Guarded filesystem-error A/B timing harness

This diagnostic compares the exact admitted old Oz runtime with a declared JavaScript derivative that suppresses Error stack capture only around numeric errno 44/54 construction when the engine capability permits it. It does not rebuild Wasm, ECL, Maxima or STACK, and does not establish production acceptance. Original and derived runtime identities remain distinct. Both arms use the same separately declared stdout-only child observer; these are guarded timings, not pristine-wrapper timings.

`run.mjs --trusted-root ROOT --arms-root ARMS --admission EVIDENCE/admission.json --output EVIDENCE --repetitions 3` requires the original e8ad producer revision, full run 40108653819 and exact Oz artifact 12568085269 ZIP digest. Admission owns complete package/source/compiler verification. The runner rechecks all 87 staged files per arm, 79 runtime assets, 77 embedded source records, matching FAS and preload; it independently derives the observer from the pinned original child. It binds exact raw derivation/proof JSON hashes and verifies all 83 other files are identical across arms. The three runtime manifests may differ only in runtime identity and maxima.js length/hash. Startup commands and the session wrapper are unchanged.

The plan is two arms × source/matching FAS × cold/reload × three repetitions: 24 measurements. Arm order rotates; every arm sees both source/FAS orderings. A fresh browser/profile is created for each cold/reload pair. Reload uses the same page/context only after the previous CAS session has terminated, is poisoned, and rejects evaluation. Every measurement has a fresh outer worker, CAS child, buffers and token. A 300-second watchdog and bounded stop acknowledgment retain partial failures; missing termination prevents reload.

Each sample measures readiness, reported STACK/wasm phases, first logical validation before grading or warmups, first positive/negative AlgEquiv grades, then ten warm grades and arithmetic calls. The combined metric is the sum of readiness + first logical + first positive; it is not end-to-end UI latency. The remaining ten-check set, STACK policy, three admitted native-program replays, 100 full-GC/live-object checks, caught-error recovery and four plotting-policy checks must pass. Native-program timings occur after warmup and are replay checks, not cold first-question measurements.

The child observer scans completed stdout lines only until READY. It counts ordered existing LOAD-BEGIN/LOAD-END/READY markers and latches anchored loadfile, Lisp-error, debug-error and syntax-error diagnostics. It emits one bounded diagnostic receipt before success or failure; failed state suppresses all later READY lines. Original child failures also latch failure. The driver requires exactly one successful receipt both after initialization and after final message draining; failures terminate the session and retain receipt/error details. The existing 16,384-character stdout tail and first fatal line are preserved; truncation is explicit. Stderr is not interposed and remains covered only by retained browser console diagnostics. No same-evaluation root-return sentinel is added, so this guard cannot prove every possible startup failure absent. No TRACE, CPU profiler, Worker replacement or FS observer is installed.

The actual child emits one experimental constructor capability receipt after restoring the original Error.stackTraceLimit descriptor and setting original errno/code fields. The driver requires numeric errno/assignedErrno/code agreement, supported writable finite capability, a strictly positive original stack limit, actual suppression, exact descriptor restoration and zero observed stack frames. Missing, malformed, duplicate, unsupported, untreated, already-disabled, unconfirmed or unrestored receipts cannot support a suppression comparison. Controls must emit no constructor receipt. These states remain separate from semantic correctness. Only eligible samples enter treatment medians and matched experimental-minus-control comparisons. The receipt cost is part of the intervention; the shared startup observer cost is part of both guarded arms.

Each attempted sample writes partial and final JSON. `report.json` is compact, with source/benchmark identities, proof hashes, per-sample metrics/status, eligible medians and paired differences; full 77-file embedded source strings are not repeated. All actual correctness and eligibility requirements must pass for the overall report to pass. n3 medians are descriptive; cache/order/runner variability remains and no speedup is assumed.

Validation is data-only: `test-harness.mjs` exercises the trusted driver against fake sessions/browser transport, and `test-startup-observer.mjs` exercises the exact derived guard/consume source with synthetic output and the retained failed draw.lisp stdout tail. The latter replay explicitly prefixes a synthetic LOAD-BEGIN because only a bounded historical tail was captured. No browser, CAS, Lisp, Wasm or artifact program was executed locally. Live engine receipt behavior and timing results remain CI evidence.
